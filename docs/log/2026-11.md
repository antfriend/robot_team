### Stage 1: the first `[ew]` reader on this fleet

*2026-11-22*

Until now `[ew]` was written (PerceptLearn, `@LAT91`) and read by nothing. Since ACT-III C3
the Cardputer no longer writes `@LAT91` at all, so the writer is dormant on current
firmware. `ttdbParseEw()` (TtdbParse) and `fleet.parse_ew()` are a pair driven by the same
28 vectors (`tests/vectors/ew_vectors.txt`). They add `prec` (default 128; `prec:0` means

here: a repeated key's last occurrence wins, and an unterminated block is no block. No
behaviour changed and nothing was flashed.

|---|---|---|---|
| 1 | `424873b` synchronous | fold took 141–288 ms (budget 100); acoustic UNVERIFIABLE in pull 2 | D3b (a job, 2 episodes a pass), D7 (rewrite when `from` moves) |
| 2 | `3b86d6f` | each rewrite took **~3 s** (`removeCuts` = whole-file rewrite of ~185 KB); acoustic UNVERIFIABLE again | D8 (a cut rider: the record leaves with its episodes), D9, D10 |
| 3 | `7059962` | as run: acoustic FAIL, a **gate-tool defect** (identical episode, trailing `---`) | accepted by Dan under the corrected tool |

The rules these runs paid for:
- ⚠ **"First write" timings say nothing about rewrites.** Run 1's 58–122 ms were appends. A
  rewrite of this ~185 KB TTDB costs ~3 s and shows as a `linkperc` worst pass of the same
  size. Never budget a "write" without saying which kind.
- ⚠ **A record derived from episodes must leave flash with them.** Acoustic writes ~1 episode
  a minute against a quota of 24, so any refold cadence slower than the cut loses the range.
  `EpisodeNode::attachCutRider` lets a derived lane add its deletions to the tier's own
  `removeCuts`. That is the general fix for any future lane that cites episodes.
- ⚠ **`catchboot.py` buffers to exit.** A live watch on it sees nothing, and a crash loses the
  log. Use `tools/stage3/holdlog.py` (line-flushed, optional reset) for any held window.
- ⚠ **`stage3_gate.records()` runs a record to the next header**, so text comparisons between
  pulls must strip the trailing `---`. That is what produced run 3's false FAIL.
- Cost against pre-stage-3: flash +9.0 KB, static RAM +1.4 KB (the fold state, static since
  D3b). The worst append in run 3 was 186 ms at 15.6 KB free heap, 14 ms under its limit.

### The observer is in the link percept (2026-11-25) — built and tested; Cardputer flashed 2026-11-26, the other five not yet

A link percept was `<peer> | link_stable | <proto>`, with the observer only in who wrote the
episode. It is now **`<observer> | link_stable_<proto> | <peer>`**: the directed edge, one
vector per radio (`Semantic/Episode.h`, THE OBSERVER IS IN THE PERCEPT). That was the point
TTG-RFC-0004 1.2 §4.7 made upstream the same day.

- **Why it had not bitten yet:** only the Cardputer authors link percepts (PerceptLearn's Rule 1
  arms only off its IMU), so in run 11 every percept's observer was 0x300 and the bar's 9 terms
  were 9 either way. The other boards' link episodes carry `said:` lines and no percept. The
  merge would have started the day a second board scored windows.
- **Both formats stay on flash and read as one.** `Consolidator::setUpgrade` hooks the two doors
  flash enters by (`feedLine`, `seedCarried`), so the keep path, the fold's EVICTING replay, the
  checkpoint's carried tallies and the bar view all read a legacy line with its record's AUTHOR:
  the node for its own lane, the `held:` agent for a copy. `fleet.py` does the same
  (`upgrade_link_triple`); `beliefs --file` needs `--node` to read legacy lines, and says so.
- **Measured on the real store:** the Cardputer's run-11 pull, 353 legacy lines, reads as the
  same 9 beliefs with identical tallies, term by term, under the new keys.
- **Pinned:** a legacy fixture read with its authors has exactly the digest of the same evidence
  written new (`0xb8766d9d`, 3 terms; it was `0xfa9dab24`, 2 terms, the held copy merged in),
  C++ and Python both. New `test_episode` "link observer upgrade" covers fold, checkpoint,
  recomputation, the cases the hook must not touch, and two observers of one peer.
- **The grammar hash moves `0xfe169cb3` → `0x42e3bb8a`.** Until all six are reflashed, boards on
  the old build will record the new ones as a SPLIT. That is item 5 doing its job, not a fault.
- `SEMANTIC_LINK_EPISODE_BUF` 1408 → 1536 (+11 B a claim; worst 1282 B, ~1463 B with a maximal
  order block). No board allocates it; a new static_assert holds it to half the 3072 B scratch,
  which `grammarHash` needs.
- ⚠ **Still open, now that it can matter:** a bar view's term count is ~(scoring observers ×
  their peers × radios). One observer is 9; the table is 32, and a full table reclaims, which
  would make the digest depend on file order. Size it before a second board scores windows.
